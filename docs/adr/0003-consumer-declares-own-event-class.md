# ADR-0003：集成事件消费方独立声明事件类

- 状态：Accepted
- 日期：2026-08-03
- 落地规则：`agent-plugin/rules/02-architecture.md` §集成事件契约

## 背景

跨服务集成事件（如 `eagle_auth_events`）需要生产方与消费方对消息结构达成一致。
常见做法是抽一个 `shared-events` jar 双方共用。

## 决策

生产方声明 `XxxIntegrationEvent`，**每个**消费方在自己模块内独立声明 `XxxMessage`，
只含本模块用得到的字段子集。**禁止**消费方 import 生产方的类，**禁止**抽共享 events jar。
两侧靠 **JSON 字段名**对齐。

## 理由

1. **共享 jar 会重建编译期耦合** —— 服务拆分的目的就是让双方能独立演进和发布；
   共享 jar 让每次事件变更都要求双方同步升级依赖版本，等于把分布式系统退化成分布式单体。
2. **消费方只需字段子集** —— 强制共用完整结构，生产方给某个消费方加字段会波及所有消费方。
3. **版本演进更平滑** —— 加字段天然向后兼容；删 / 改名 / 改类型走 `eventVersion` 升版 + 双发灰度。

## 代价（明知而接受）

**生产方改字段名时，消费方编译期不会红。** 这是本决策最主要的风险敞口。

缓解措施（已落地）：生产方 `IntegrationEventContractTest` 把事件样例序列化到 `docs/contracts/*.json`
并提交版本库；消费方同名测试读取该文件反序列化并断言关键字段非空。
字段改名会让契约文件产生 diff 且消费方测试立刻失败。
`docs/contracts` 已声明为消费方 test 任务的输入，避免 Gradle 判 UP-TO-DATE 跳过校验。

## 备选方案

- **共享 events jar** —— 否决，理由见第 1 点
- **引入 Pact / Spring Cloud Contract** —— 暂缓：当前只有 3 个集成事件、1 对生产消费方，
  上述轻量契约测试已覆盖同样的失败场景；事件数量或消费方显著增长后可重新评估

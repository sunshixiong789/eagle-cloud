# ADR-0001：禁止物理外键

- 状态：Accepted
- 日期：2026-08-03
- 落地规则：`agent-plugin/rules/04-data.md` §强制禁止物理外键

## 背景

JPA 的 `@JoinColumn` / `@CollectionTable` 默认会生成 `FOREIGN KEY` 约束。
DB 层的引用完整性看起来是"免费的正确性"，代价却在后面才显现。

## 决策

**所有表禁止 `FOREIGN KEY` / `REFERENCES`。** 凡会让 Hibernate 建 FK 的注解，
一律显式 `foreignKey = @ForeignKey(ConstraintMode.NO_CONSTRAINT)`。
引用完整性由聚合根业务方法和应用层校验保证。

## 理由

1. **阻塞服务拆分** —— 本项目以「微服务拆分就绪」为目标（auth 已拆出）。跨服务的表之间不可能维持 FK；
   若一开始就建了，拆分时要先做一轮删约束，且删的过程中完整性无人兜底。
2. **阻塞分库分表** —— ShardingSphere 等中间件下，FK 跨分片无法成立。
3. **阻塞数据迁移与批量导入** —— 导入顺序被 FK 拓扑绑死，大批量场景要反复开关约束。
4. **与 DDD 聚合边界冲突** —— 跨聚合只存 ID 是聚合设计的要求；FK 会把本该松耦合的聚合在存储层焊死。

## 代价（明知而接受）

- 脏数据不再被 DB 拦截，依赖应用层纪律和测试
- 需要定期对账 / 巡检任务发现孤儿引用

## 备选方案

**保留 FK、拆分时再删** —— 否决：迁移期风险最高的时刻恰好是约束最不可靠的时刻，
且「以后再删」在实践中等于永远不删。

# /new-adr — 新建架构决策记录

规则记 **what**，ADR 记 **why**。没有 why 的规则，几个月后要么被当成教条绕过，要么在前提失效后仍被固守。

## 何时该写

只写**有代价、有争议、难反悔**的决策：

- 引入 / 移除基础设施依赖（starter、中间件、框架）
- 定下约束所有人的红线（禁 X、必须 Y）
- 两个都说得通的方案里选了一个
- 推翻此前的决策

**不写**：显而易见、无争议、改起来没成本的。ADR 不是变更日志。

## 执行步骤

1. **取下一个编号**

   ```bash
   ls docs/adr/[0-9]*.md | sed 's|.*/||' | cut -d- -f1 | sort -n | tail -1
   ```
   编号连续递增，四位补零。

2. **建文件** `docs/adr/NNNN-kebab-title.md`，用下方模板

3. **更新** `docs/adr/README.md` 末尾的索引表

4. **回填规则** —— 在 `agent-plugin/rules/` 对应条目后加链接：
   ```markdown
   **所有表禁止 `FOREIGN KEY`** —— 理由见 [ADR-0001](../../docs/adr/0001-no-physical-foreign-keys.md)
   ```

## 模板

```markdown
# ADR-NNNN：<标题>

- 状态：Proposed
- 日期：YYYY-MM-DD
- 落地规则：`agent-plugin/rules/XX-xxx.md` §<小节>

## 背景

<当前处境、约束、促成决策的诱因。写事实，不写结论。>

## 决策

<一句话说清做什么。用祈使句，可执行、可验证。>

## 理由

<为什么这么选，按重要性排序。每条尽量落到具体后果，而非抽象原则。>

## 代价（明知而接受）

<诚实写出放弃了什么、引入了什么风险，以及有无缓解措施。
这一段最容易被略过，也最有价值 —— 没有代价的决策不需要 ADR。>

## 备选方案

<认真考虑过并否决的方案 + 否决理由。>
```

## 硬规则

- **已 `Accepted` 的 ADR 不修改内容**。要改就新写一篇标 `Supersedes: NNNN`，
  并把旧的状态改为 `Superseded by NNNN` —— 决策的演进过程本身是有价值的信息
- 「代价」段不许留空。写不出代价，说明这个决策不值得记 ADR

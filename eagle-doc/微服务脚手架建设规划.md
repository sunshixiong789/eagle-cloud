## 二、包命名问题分析

| 模块名 | 实际包名 | 问题 | 建议 |
|--------|----------|------|------|
| `eagle-jpa-starter` | `com.eagle.datajpa` | 不一致 | 包名应改为 `com.eagle.jpa` 或模块名统一为 `eagle-data-jpa-starter` |
| `eagle-resource-server-starter` | `com.eagle.resource` | 不一致 | 包名应改为 `com.eagle.resourceserver` 或 `com.eagle.resource.server` |
| `eagle-feign-starter` | `com.eagle.feign` | 一致 | 但模块为空壳，需补全 |
| `eagle-common-starter` | `com.eagle.common` | 一致 | -- |
| `eagle-system-server` 内 `upms` | `com.eagle.system.base` | 技术缩写 | `upms` 是 User Permission Management System 缩写，不符合 DDD 业务域命名规范（应使用名词）。因代码量已大，建议暂缓改名，后续新模块严格遵循规范 |
| `eagle-gateway-server` | `com.eagle.gateway` | 一致 | 但模块为空壳 |

**根 build.gradle 已声明但未使用的版本：**
- `redissonVersion: 4.3.0` -- Redis 是计划中的，但尚无独立 starter
- `caffeineVersion: 3.2.0` -- 本地缓存，已用于 system-server

## 四、关键设计建议

### 1. Redis Starter 设计（P0）

`eagle-resource-server-starter` 已经依赖了 `spring-boot-starter-data-redis`，但：
- 它耦合在资源服务器里，非资源服务器的服务（如纯内部服务）无法独立使用 Redis
- 建议将 Redis 配置提取为 `eagle-redis-starter`，resource-server-starter 改为依赖它

```
eagle-redis-starter/
  config/RedissonConfig.java          # RedissonClient Bean
  config/RedisCacheConfig.java        # CacheManager
  util/RedisLockUtil.java             # 分布式锁工具
  util/RedisRateLimiter.java          # 限流计数器
```

### 2. Gateway 完善要点（P0）

当前 `eagle-gateway-server` 仅有一个启动类，需要补充：
- **JWT 鉴权 GlobalFilter**：解析 Token、校验黑名单、透传用户信息到下游
- **路由配置**：注册中心自动发现（Nacos）+ 手动配置兜底
- **限流**：Sentinel 或 Redis 令牌桶
- **跨域**：统一 CORS 配置
- **请求日志**：记录请求耗时、状态码

### 3. Feign Starter 完善要点（P0）

```
eagle-feign-starter/
  config/FeignConfig.java
    # 请求拦截器：从 SecurityContext 提取 Token 注入 Header
    # 错误解码器：将下游 4xx/5xx 转换为 AppException
    # 日志级别配置
```

### 4. 消息队列与领域事件（P1）

当前领域事件（如 `AccountRegisteredEvent`）只在单体内部通过 Spring Modulith 发布。微服务化时需要：
- 引入 `spring-modulith-events-kafka`（或 RabbitMQ）
- 事件类统一放在 `eagle-common-starter`（已有部分在 `com.eagle.common.event`）
- 消费方使用 `@TransactionalEventListener` + `@Async`

## 五、推荐实施顺序

**第一阶段（1-2 周）：基础设施补齐**
1. 新建 `eagle-redis-starter`
2. 完善 `eagle-feign-starter`
3. 完善 `eagle-gateway-server`（路由 + JWT 鉴权）
4. 接入 Nacos 服务注册

**第二阶段（2-3 周）：高可用增强**
5. Sentinel 限流熔断（Gateway + 注解方式）
6. 分布式链路追踪
7. 操作日志审计 Starter

**第三阶段（3-4 周）：业务扩展**
8. 消息队列 + 领域事件外部化
9. 文件存储服务
10. 消息通知服务

**第四阶段（按需）**
11. Seata、多租户、代码生成器、Docker/K8s/CI-CD

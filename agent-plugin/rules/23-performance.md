# 性能规范

性能规则只保留项目红线和 Eagle 常见风险；通用优化技巧按场景判断。

## 数据库

- 防 N+1：列表页不在循环内触发懒加载；使用投影、`@EntityGraph`、fetch join 或批量查询。
- 慢查询阈值：开发/测试超过 1s 必须排查；生产由监控持续跟踪。
- 高频查询字段必须有索引；多租户表索引以 `tenant_id` 为前导。
- 深翻页（如 `page > 100`）改游标分页或限制最大页数。
- 批量写入使用分批提交，避免超大事务。

## 连接池与事务

- Druid、Hibernate batch、JPA fetch size 等按服务负载调优，不为单个慢接口盲目扩大连接池。
- 写事务保持短小；事务内避免远程调用、慢 IO 和大批量循环。
- 只读查询使用 `@Transactional(readOnly = true)`。

## 缓存

- 高频稳定查询优先缓存，但不得缓存权限强相关、租户隔离不清或敏感数据。
- 缓存 key、TTL、击穿/穿透/雪崩防护遵守 `14-cache.md`。
- 聚合更新后的缓存失效优先事件驱动，见 `08-concurrency.md`。

## 异步与阻塞 IO

- `@Async` 必须使用项目定义的线程池；不要默认落到不可控 executor。
- CPU 密集、阻塞 IO、定时任务、MQ 消费使用隔离线程池。
- 异步任务必须传递必要的 trace、tenant、安全上下文。

## 大对象与 HTTP

- 大文件和大结果集使用流式处理；不要一次性读入内存。
- 远程调用必须设置连接、读取超时，并结合 `21-resilience.md` 做熔断/重试/限流。
- 不在事务中等待慢 HTTP 调用，除非分布式事务规则明确要求。

## 监控与压测

- 暴露 Micrometer 指标：QPS、P95/P99、错误率、慢 SQL、连接池、线程池、缓存命中率、MQ 堆积。
- 新关键接口上线前至少给出本地或压测环境的吞吐、延迟、资源占用结论。

## 禁止清单

- 循环内查库、循环内远程调用、循环内 `INFO` 日志。
- 无索引分页和无限制导出。
- `Thread.sleep()` 替代异步等待。
- 为掩盖慢 SQL 直接加缓存或调大连接池。

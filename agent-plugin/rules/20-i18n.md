# 国际化规范（i18n）

技术栈：Spring `MessageSource` + `LocaleResolver`（`Accept-Language` 头）+ `ResourceBundle`。

## 文件组织

```
{module}/src/main/resources/
└── i18n/
    ├── messages.properties           # 默认（zh_CN）
    ├── messages_en_US.properties
    ├── messages_zh_CN.properties
    └── messages_zh_TW.properties
```

- 默认 locale：`zh_CN`
- 支持语言通过 `LocaleResolver` 配置，`Accept-Language` 自动协商
- 模块化：每个 starter / 服务可独立维护 messages，自动合并

## Key 命名规范

格式：`{domain}.{action}.{result}` 或 `error.{domain}.{code}`

```properties
# 错误消息（与 ErrorCode 映射）
error.order.not_found          = 订单不存在
error.order.already_paid       = 订单已支付
error.order.insufficient_stock = 库存不足
# 业务消息
notification.order.created     = 您的订单 {0} 已创建
notification.order.shipped     = 订单 {0} 已发货，物流单号 {1}
# 字段名（用于校验消息）
field.order.no                 = 订单号
field.order.amount             = 金额
```

- 全小写 + `.` 分隔 + `_` 词内连接
- 占位符使用 `{0} {1}`（`MessageFormat` 风格），**不**用 `${}`
- 与 ErrorCode 严格对齐：`OrderErrorCode.ORDER_NOT_FOUND` → `error.order.not_found`

## ErrorCode 联动

```java
public enum OrderErrorCode implements ErrorCode {
    ORDER_NOT_FOUND(30001, "error.order.not_found", "订单不存在"),
    ORDER_ALREADY_PAID(30002, "error.order.already_paid", "订单已支付");

    private final ErrorCode.Meta meta;

    OrderErrorCode(int code, String messageKey, String defaultMessage) {
        this.meta = new ErrorCode.Meta(code, messageKey, defaultMessage);
    }

    @Override
    public ErrorCode.Meta meta() { return meta; }
}
```

- 第二个参数为 i18n key（**必须**在三种语言文件中都存在）
- 第三个参数为兜底默认消息（i18n 文件缺失时使用）
- 全局异常处理器根据 `Accept-Language` 自动从 `MessageSource` 解析
- `getCode()` / `getMessageKey()` / `getDefaultMessage()` 由 `ErrorCode` 接口的 default 方法提供，枚举**无需**再覆写

## Bean Validation 消息

```java
public class CreateOrderRequest {
    @NotBlank(message = "{validation.order.no.required}")
    private String orderNo;

    @Min(value = 1, message = "{validation.order.amount.min}")
    private BigDecimal totalAmount;
}
```

```properties
# i18n/messages_zh_CN.properties
validation.order.no.required = 订单号不能为空
validation.order.amount.min  = 金额必须大于 0
```

校验消息必须用 `{key}` 形式（不直接写中文），**不**硬编码。

## Locale 解析顺序

`eagle-common-starter` 默认 `LocaleResolver` 解析顺序：

1. URL 参数 `?lang=en_US`（开发期/调试）
2. `Accept-Language` HTTP 头
3. JWT claim `locale`（已登录用户偏好）
4. 用户配置文件中的 locale
5. 默认 `zh_CN`

## 占位符消息

```java
// ✅ 在异常或日志中使用
String message = messageSource.getMessage(
                "notification.order.created",
                new Object[]{orderNo},
                LocaleContextHolder.getLocale()
        );

// ✅ 简便方法（项目封装）
i18n.

format("notification.order.created",orderNo);
```

**禁止**字符串拼接：`"订单 " + orderNo + " 已创建"`（无 i18n 能力）。

## 日期 / 货币 / 数字

```java
// ✅ 使用 Locale 敏感格式化
DateTimeFormatter formatter = DateTimeFormatter
                .ofLocalizedDateTime(FormatStyle.MEDIUM)
                .withLocale(LocaleContextHolder.getLocale());

NumberFormat.

getCurrencyInstance(locale).

format(amount);
```

接口响应中：

- 金额字段返回**原始数值**（`BigDecimal`），由前端按 locale 格式化
- 日期返回 ISO 8601（`2026-04-30T10:00:00Z`），前端按 locale 显示

## 日志 i18n

**业务日志不做 i18n**——日志面向运维和开发者，统一英文/中文即可。仅"对最终用户可见的消息"需 i18n。

## 编码

- 所有 properties 文件**必须 UTF-8**（IDEA 默认 ISO-8859-1 需手工改）
- `application.yml`：`spring.messages.encoding: UTF-8`

```yaml
spring:
  messages:
    basename: i18n/messages
    encoding: UTF-8
    cache-duration: 3600s        # 生产；开发期 0
    fallback-to-system-locale: false
```

## 缺失 Key 处理

```yaml
spring.messages.use-code-as-default-message: true
```

key 缺失时返回 key 名（开发期定位问题），**不**抛 `NoSuchMessageException`。

## 测试

```java

@Test
void shouldReturnEnglishMessage() {
    LocaleContextHolder.setLocale(Locale.US);
    String msg = errorCode.getLocalizedMessage();
    assertThat(msg).isEqualTo("Order not found");
}
```

每种支持的 locale 至少一个用例验证关键消息。

## 禁止清单

- 禁止业务代码硬编码中文 / 英文消息
- 禁止仅在 `messages.properties` 加 key 而不同步翻译版本（CI 校验）
- 禁止用 `${}` 作 i18n 占位符（与 SpEL 冲突）
- 禁止跨 locale 缓存格式化结果
- 禁止前端写死中文消息（用错误码 + i18n key 统一渲染）

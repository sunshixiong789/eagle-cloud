# 日志规范

技术栈：SLF4J + Logback，接入 `eagle-tracing-starter` 输出 traceId。日志规则只记录项目红线；占位符、级别选择等通用写法按模型默认能力和现有代码执行。

## Logger

- 优先使用 Lombok `@Slf4j`；显式声明时使用 `private static final Logger`。
- 禁止公开、可变或实例级 Logger。

## 级别与内容

- `INFO`：关键业务里程碑、跨服务调用摘要、MQ 发送/消费摘要、任务开始/结束。
- `WARN`：可恢复但需要关注的异常路径、降级、限流、外部依赖不稳定。
- `ERROR`：需要排查或告警的失败，异常对象作为最后一个独立参数传入。
- `DEBUG/TRACE`：请求体、响应体、SQL 参数、中间分支、高频循环细节。

## 必须埋点的操作

- 状态机变更：创建、支付、取消、退款、注册、注销、授权、回收。
- 涉及金额、库存、配额的写操作。
- 远程调用、MQ、分布式事务、分布式锁、缓存双写的边界。
- 外部依赖：支付、短信、OSS、第三方 API。
- 定时任务、异步任务的开始、结束、处理量、耗时、结果。
- 登录、登出、鉴权、Token 刷新、权限失败。

## MDC

- traceId/spanId 由 tracing starter 注入。
- 自定义 MDC 必须 `try/finally` 成对 `put/remove`，避免线程池污染。
- 异步任务要通过 `TaskDecorator` 或项目统一线程池传递必要上下文。

## 敏感数据

- 禁止在日志输出密码、Token、Cookie、验证码、密钥、身份证、银行卡、完整手机号、完整请求体。
- 手机、身份证、银行卡等只输出脱敏值；文件上传只记录文件名、大小、MIME、hash。
- 业务异常不要把下游原始敏感响应直接透传到日志。

## 禁止清单

- `System.out`、`printStackTrace()`。
- 字符串拼接日志和丢失堆栈的异常日志。
- Controller/Service 每层都打进入/退出日志。
- 在循环内打 `INFO`。
- 将完整入参、出参、请求体、响应体打到 `INFO`。

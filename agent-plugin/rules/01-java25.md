# Java 25 语言基线

本仓库 `JavaLanguageVersion.of(25)`，**未开启 `--enable-preview`** —— 只能用已 final 的特性。
下表是新代码的默认写法；存量老写法不强制回改，但**新代码不得再用左列**。

| 场景 | ❌ 旧写法 | ✅ 新写法 |
|---|---|---|
| DTO / 值对象 / 事件载荷 | `class` + Lombok `@Data` | `record` |
| 封闭的类型层级 | `interface` + 注释约定 | `sealed interface ... permits` |
| 类型判断分支 | `if (x instanceof A) { A a = (A) x; ... }` | `switch` 模式匹配 |
| 解构对象 | 逐个 getter | record pattern |
| 集合首尾 | `list.get(0)` / `list.get(size-1)` | `getFirst()` / `getLast()` |
| 自定义分组/滑窗 | 手写循环 | `Stream.gather(...)` |
| 局部变量 | 冗长泛型 | `var`（右侧类型自明时） |
| 多行字符串 | `"..." + "\n" + "..."` | text block `"""` |

## record —— DTO 的默认形态

已用于 47 个主代码文件，是本项目的既定写法。

```java
public record UserMessageResponse(
        Long id,
        MessageCategory category,
        String title,
        boolean isRead,
        LocalDateTime createTime
) {
    /** 领域对象 → DTO 的静态工厂，适用于无跨聚合查询的简单映射 */
    public static UserMessageResponse of(UserMessage m) {
        return new UserMessageResponse(m.getId(), m.getCategory(), m.getTitle(),
                m.isRead(), m.getCreateTime());
    }
}
```

- 请求 DTO、响应 DTO、值对象、集成事件载荷、内部传参 → 一律 `record`
- **紧凑构造器**做不变式校验：`public record Money(BigDecimal amt) { public Money { Objects.requireNonNull(amt); } }`
- record 上**不要**加 Lombok（`@Data` / `@Builder` 与 record 语义冲突）
- JPA `@Entity` **不能**是 record（Hibernate 需要可变对象 + 无参构造），聚合根仍是 class

映射逻辑的归属见 `02-architecture.md`：简单映射用 record 静态工厂，涉及跨聚合/多来源用 `application/mapper/` 下的 `@Component` Mapper。

## sealed —— 封闭领域建模

用于「取值集合封闭且需要穷尽处理」的场景：

```java
// ✅ 领域事件封闭层级——新增事件时所有 switch 会编译报错，强制补全分支
public sealed interface AccountEvent
        permits AccountRegistered, AccountFrozen, AccountDeleted { }

public record AccountRegistered(Long accountId, String phone) implements AccountEvent { }
public record AccountFrozen(Long accountId, String reason)     implements AccountEvent { }
public record AccountDeleted(Long accountId)                   implements AccountEvent { }
```

适用：领域事件层级、状态机结果、命令类型、解析结果（成功/各类失败）。

**不适用**：持久化状态字段仍用 `enum`（`@Enumerated(EnumType.STRING)`），因为要存库；`sealed` 用于**行为分派**，`enum` 用于**存储取值**。

## 模式匹配 —— 取代 if-else / 类型转换链

```java
// ❌ 旧
if (event instanceof AccountRegistered) {
    AccountRegistered e = (AccountRegistered) event;
    notify(e.accountId(), e.phone());
} else if (event instanceof AccountFrozen) {
    ...
}

// ✅ switch + record pattern：解构 + 穷尽检查一步到位
switch (event) {
    case AccountRegistered(Long id, String phone) -> notify(id, phone);
    case AccountFrozen(Long id, String reason)    -> kickOffline(id, reason);
    case AccountDeleted(Long id)                  -> purge(id);
}
```

- 对 `sealed` 类型 switch **不要写 `default`** —— 省略后新增子类型会编译失败，这正是要的效果
- 带条件用 `when`：`case AccountFrozen(var id, var r) when r.isBlank() -> ...`
- `null` 显式处理：`case null -> ...`，不要靠外层 if

## Stream 与集合

```java
// ✅ toList() 取代 collect(Collectors.toList())
List<UserResponse> list = users.stream().map(mapper::toResponse).toList();

// ✅ Sequenced Collections（Java 21+）
var first = list.getFirst();
var last  = list.getLast();
var reversed = list.reversed();

// ✅ Stream Gatherers（Java 24 final）：滑窗 / 定长分批
var batches = ids.stream().gather(Gatherers.windowFixed(500)).toList();
```

批量落库、批量调用下游时用 `windowFixed` 分批，**不要**手写 `for` + 计数器切片。

## 虚拟线程

[AsyncConfig.java](eagle-starter/eagle-common-starter/src/main/java/com/eagle/common/config/AsyncConfig.java) 已支持，由 `spring.threads.virtual.enabled` 切换，Bean 名恒为 `taskExecutor`：

| 模式 | 执行器 | 背压手段 |
|---|---|---|
| 平台线程（默认） | `ThreadPoolTaskExecutor` | 有界队列 + `CallerRunsPolicy` |
| 虚拟线程 | `SimpleAsyncTaskExecutor(virtual=true)` | `eagle.async.concurrency-limit`（默认无界） |

**开启虚拟线程前必须做的两件事**：

1. 设 `eagle.async.concurrency-limit` 为正数 —— 否则无背压，会瞬间打爆下游（尤其 DB 连接池）。取值参考连接池上限。
2. 排查 `synchronized` 持有期间的阻塞 IO —— 会 pin 住载体线程抵消收益，改用 `ReentrantLock`。

虚拟线程适合阻塞 IO 密集；**CPU 密集任务仍用平台线程池**，不要指望虚拟线程提速。

## ScopedValue 与 ThreadLocal

本仓库有 21 处 `ThreadLocal`（`TenantContextHolder`、`PressureTestContext`、`DataSourceContextHolder` 等），跨线程传递由 [ContextPropagationConfig](eagle-starter/eagle-common-starter/src/main/java/com/eagle/common/observability/ContextPropagationConfig.java) 统一处理。

- **既有的 filter 作用域上下文保持 `ThreadLocal`** —— 它们是 `set`/`clear` 可变模型，与 `ScopedValue` 的不可变+词法作用域模型不兼容，硬迁要改造整条过滤器链，收益不抵风险
- **新增上下文**若作用域是词法闭合的（一段调用内有效、无需中途改写），优先 `ScopedValue`：虚拟线程下无 `ThreadLocal` 的内存与继承开销

```java
private static final ScopedValue<String> TRACE_TAG = ScopedValue.newInstance();
ScopedValue.where(TRACE_TAG, tag).run(() -> handle(req));
```

无论哪种，**`ThreadLocal` 用完必须 `remove()`（`try/finally`）** —— 虚拟线程数量巨大，泄漏后果比平台线程更严重。

## 其他

- **Optional**：只用作返回值表达"可能没有"，**不要**作字段、不要作方法参数
- **text block**：多行 SQL / JSON / 提示词用 `"""`，不要字符串拼接
- **var**：右侧类型自明时用（`var user = new User()`）；`var list = service.find()` 这种看不出类型的不要用
- **不要使用**：Structured Concurrency（Java 25 仍是 preview，本项目未开 `--enable-preview`）

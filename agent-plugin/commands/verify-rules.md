# /verify-rules — 规则一致性自检

规则是 **always-on 注入**的：写错会让模型稳定地生成错误代码，而且错误会一直复现。
本命令断言规则文本里每一个"可验证的事实"，把规则漂移变成可发现的。

## 执行

```bash
./agent-plugin/scripts/verify-rules.sh
```

## 校验项

| # | 校验 | 抓什么问题 |
|---|---|---|
| 1a | 规则里 `[Xxx](path/Xxx.java)` 链接的文件存在 | 源码链接失效（重构/删除后没跟着改） |
| 1b | 模型会直接调用的 Eagle 核心 API 存在 | 规则教了**不存在的 API**，照写编译失败 |
| 1c | 规则声明「不存在」的 API 确实不存在 | 能力回归了但规则还在说没有，反向误导 |
| 2 | 规则写的表名在 `@Table` 中出现 | 表名前缀/命名漂移 |
| 3 | 规则写的配置键真实存在（prefix 命中还须 name/字段也命中） | 配置项改名或删除；**光比 prefix 会让 `eagle.{prefix}.任意后缀` 假通过** |
| 4 | 存量违例台账数字与实测一致（含非 record 的 DTO 数） | 台账过期（数字天然会变） |
| 5 | 规则里的 Gradle 模块路径在 `settings.gradle` 存在 | 模块重命名后命令照抄必失败 |
| 6 | 规则文件之间交叉引用无断链 | 规则重编号后的漏网引用 |

## 结果处理

- **退出码 0** — 规则与代码一致，无需动作
- **退出码 1** — 输出偏差清单，逐条判断：
  - 代码是对的、规则过期 → **改规则**（多数情况）
  - 规则是对的、代码违规 → 改代码，或记入 `07-checklist.md` 存量违例台账
  - 台账数字类偏差 → 直接把新数字更新进 `07-checklist.md`，属正常维护

## 何时跑

- 改动 `agent-plugin/rules/**` 之后
- 删除/重命名 starter、服务模块、核心类之后（**最容易打穿规则的场景**）
- PR 前，与 `/check-arch` 配合

## 已知局限

只校验**可机械验证**的断言（类名、表名、配置键、路径、数字）。规则里的设计判断和取舍理由无法自动校验，仍需人工评审。

规则中作为**反例**出现的配置键（`eagle.xxx.enabled` / `eagle.tenant.enabled` / `eagle.datasource.enabled`）
在脚本 `key_ignored()` 中登记豁免——它们由校验项 1c 反向保证"确实不存在"。
新增这类"规则声明它不存在"的键时，两处要一起加。

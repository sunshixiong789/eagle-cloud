# 国际化（i18n，通用）

> 跨平台通用约束。具体库选型（react-i18next / formatjs / Taro 内置 i18n / RN i18n-js）按项目栈选。

## 何时启用 i18n

- 产品需要支持 ≥ 2 种语言 → 启用
- 单语言但**可能**未来扩多语言 → 现在不抽 key，等真要扩再统一改（YAGNI）
- 仅做"中文 + 极少英文"提示 → 不必启用，业务字符串直接写

## 文件组织

```
src/
├── shared/
│   └── i18n/
│       ├── index.ts            # 初始化 + 暴露 t() 或 useTranslation()
│       └── locales/
│           ├── zh-CN.json
│           ├── en-US.json
│           └── zh-TW.json
```

- **不在 feature 内**保留 i18n 文件——所有 messages 集中在 `@shared/i18n/locales/`
- Locale 文件用 JSON（便于工具协作 + 与 Crowdin / Lokalise 等翻译平台集成）
- 文件名用 BCP 47 标准：`zh-CN`、`en-US`、`zh-TW`、`ja-JP`

## Key 命名规范

格式：`{domain}.{action}.{result}` 或 `error.{domain}.{code}`

```jsonc
// shared/i18n/locales/zh-CN.json
{
  "common": {
    "ok": "确定",
    "cancel": "取消",
    "loading": "加载中..."
  },
  "auth": {
    "login": {
      "title": "登录",
      "username_required": "请输入用户名",
      "submit": "立即登录"
    },
    "error": {
      "invalid_credentials": "用户名或密码错误"
    }
  },
  "order": {
    "list": {
      "empty": "暂无订单"
    },
    "status": {
      "created": "已创建",
      "paid": "已支付",
      "shipped": "已发货"
    }
  }
}
```

约定：

- 全小写 + `.` 分隔层级 + `_` 词内连接
- 第一层用 `common` / `<feature 词根>` / `error`
- 占位符用 `{count}` / `{name}` 风格（i18next / formatjs 通用）
- 与后端的 i18n key **不强求一致**（前端用户面 vs 后端日志面），但错误码消息可对齐：前端 `error.order.not_found` ↔ 后端 `error.order.not_found`

## 占位符与复数

```ts
// ✅ 占位符
t('order.list.title', { count: 5 });   // "你有 5 个订单"

// ✅ 复数（i18next）
{
  "order.count_one": "你有 {count} 个订单",
  "order.count_other": "你有 {count} 个订单"
}

// ❌ 字符串拼接
t('order.list.prefix') + count + t('order.list.suffix');  // 翻译难
```

## Locale 解析顺序

```
1. URL 参数 ?lang=en-US（开发调试）
2. JWT claim / 用户配置中的 locale
3. 浏览器 navigator.language（Web）/ Taro.getSystemInfoSync().language / NativeModules.SettingsManager.settings.AppleLocale (RN)
4. 默认 zh-CN
```

变更 locale 必须**持久化到 store**（Zustand persist），刷新后仍生效。

## 各平台库选型推荐

| 平台 | 推荐库 |
|---|---|
| **Web** | `react-i18next` 或 `formatjs / react-intl` |
| **React Native** | `react-i18next` 或 `i18n-js` + `expo-localization` |
| **Taro** | `react-i18next`（H5 / RN 端原生支持）；小程序端注意 SSR 不适用，初始化在 `app.tsx` |

跨端**统一用 react-i18next** 最省心——同一份 messages + 同一份 hook (`useTranslation`) 跨 web / RN / Taro。

## 业务层使用

```tsx
// ✅ Component 用 hook
function LoginButton() {
  const { t } = useTranslation();
  return <Button>{t('auth.login.submit')}</Button>;
}

// ✅ Page 编排时透传
function LoginPage() {
  const { t } = useTranslation();
  // ...
  return <Form title={t('auth.login.title')} />;
}

// ❌ 业务字符串硬编码
return <Button>立即登录</Button>;

// ❌ 在 store 中保存翻译后的字符串
useStore.getState().setMessage('订单已创建');   // 用户切换 locale 后不变
```

**store 与 query 内只保存 i18n key 或原始数据**，不保存翻译后字符串——切换 locale 时无法自动更新。

## 错误消息 i18n

通用模式（与后端 `rules/20-i18n.md` 对齐）：

```ts
// API 返回结构
{
  "errorCode": 30001,
  "messageKey": "error.order.not_found",
  "message": "订单不存在"     // 后端按 Accept-Language 渲染好的兜底
}

// 前端选择：
// 1) 优先用前端 messages 渲染（与 backend message 解耦）
// 2) 后端 messageKey 在前端 locale 里不存在 → 用 backend message 兜底
const errMsg = i18n.exists(error.messageKey)
  ? t(error.messageKey)
  : error.message;
```

## 与 Accept-Language 请求头

`@shared/api/http.ts` 拦截器中**自动**附加 `Accept-Language` 头：

```ts
// shared/api/http.ts
http.interceptors.request.use((config) => {
  config.headers['Accept-Language'] = i18n.language;
  return config;
});
```

让后端能按当前 locale 返回错误消息。

## 禁止清单

- 禁止业务字符串硬编码（用 `t()`）
- 禁止 store / query 缓存翻译后字符串（只缓存 key 或原始数据）
- 禁止字符串拼接组合翻译片段（用占位符）
- 禁止在 feature 内单独保留 messages 文件（集中 `@shared/i18n/locales/`）
- 禁止用通用 `useEffect` 在每个组件单独调 `i18n.changeLanguage()`（只在用户主动切换时调用）
- 禁止 BCP 47 编码不一致（`zh-CN` 与 `zh_CN` 不要混用）

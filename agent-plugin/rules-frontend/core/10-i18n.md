# 国际化（i18n）

## 启用条件

- 面向多语言用户、后台运营、多端共用文案或后端返回 i18n key 时启用。
- 纯内部一次性页面可暂不启用，但不要把后端错误消息写死在组件里。

## 组织

推荐按 feature 拆分 messages：

```text
src/shared/i18n/
src/features/<feature>/i18n/
```

key 使用命名空间：`feature.section.name`，错误消息与后端 `errorCode` / i18n key 对齐。

## 使用

- Component 只渲染已翻译文案，不拼接业务句子。
- 金额、日期、数字由前端按 locale 格式化；后端返回原始值。
- 请求带 `Accept-Language`；401/错误拦截统一转换错误码或 key。
- 占位符用于变量，避免字符串拼接。

## 平台选型

- Web：`i18next` / `react-i18next`。
- RN：同 Web，注意资源懒加载和本地存储。
- Taro：优先轻量字典封装或兼容 i18next 的薄层。

## 禁止清单

- 前端写死后端错误中文。
- 在 API 层直接 toast 翻译后的文案。
- DTO 字段为适配 UI locale 改名或改类型。
